# Pinned production dependency closure for reproducible builds.
#
# WHY: pyproject.toml intentionally uses loose (>=) ranges so the package
# stays installable in a wide range of environments (it is a library + CLI).
# For the PRODUCTION container and any build that must be byte-reproducible,
# pip resolves against THIS file so the exact same versions are installed
# every time, regardless of what happens to be newest on PyPI that day.
#
# HOW IT IS USED:
#   pip install --no-cache-dir . -c constraints.txt
# (see Dockerfile). A constraints file only pins versions for packages that
# actually get installed; it never forces an unused package to be installed.
#
# HOW TO UPDATE (do this deliberately, not incidentally):
#   1. Recreate a clean venv and `pip install .`
#   2. `pip freeze` and copy the resolved versions here.
#   3. Run the full test suite (`pytest`) against the new set.
#   4. Commit the updated constraints.txt in its own change.
#
# These versions are exactly the ones the committed test suite is green
# against.
