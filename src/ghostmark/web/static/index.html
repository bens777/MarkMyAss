    What MarkMyAss actually removes

    Signal-based, not provider-magic — support depends on the signal type, not just which AI made the file.

    Reliably supported

    • Hidden Unicode and invisible text characters
    • EXIF / XMP / IPTC metadata (JPEG, PNG, WebP)
    • PDF document metadata (DocInfo + XMP)
    • PNG metadata
    • Supported file-level provenance signals
    • Independent metadata verification with ExifTool

    Current limits

    • C2PA / Content Credentials support is partial
    • Claude, Gemini, and GPT statistical model-level watermarks are currently UNKNOWN — no public verifier exists to confirm removal
    • MarkMyAss never claims "100% AI-undetectable"

    What "VERIFIED CLEAN" means

    MarkMyAss shows VERIFIED CLEAN only when a supported signal was actually found before cleaning, its own re-inspection confirms it's gone, and every independent verifier that could run (ExifTool, and c2patool where applicable) agrees too. It is not a claim that the file contains no possible identifying signal whatsoever — only that the specific, supported metadata categories MarkMyAss targets are independently confirmed gone. See the AI Watermark Lab for the full, honestly-scored capability matrix.

    Is MarkMyAss only for Claude?

    No. MarkMyAss is not limited to Claude. It works across supported watermark and provenance signal types, including hidden Unicode and common file metadata. Its support depends on the signal type, not just the AI provider.

    Best use cases

    Where MarkMyAss is genuinely reliable — not a universal AI-detection eraser, but strong at what it actually does.

    • Cleaning metadata before publishing PDFs or images
    • Removing author, creator, GPS, and related metadata fields
    • Cleaning hidden Unicode from copied AI-generated text
    • Checking files for supported provenance metadata before you rely on them
    • Independently verifying that supported traces were actually removed — not just trusting a single tool's word for it
